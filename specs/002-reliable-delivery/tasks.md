# 002 — задачи

Порядок — сверху вниз. Спецификация — [spec.md](spec.md). Этап 1 — только `messenger-ui` и `wolp-android`.

## Проверки до кода

- [ ] T200 Сервер меняет `updatedAt` чата на каждое сообщение и не меняет от прочтения — проверить запросом на стенде. Если нет — 3.2 строится на нажатиях и push, отметить в спецификации
- [ ] T201 Снять с телефона владельца `logcat` за случай Б, если повторится до правки: есть ли `push: drop`, пришёл ли `notificationTap`, был ли запрос истории

## Признак разрыва (3.1)

- [ ] T202 `syncedEpoch` у истории чата; чат устарел, если номер не равен текущему. Тесты: разрыв → устарели все; чтение при закрытом сокете не считается
- [ ] T203 Устаревший чат перечитывается: открытый — после соединения, остальные — при открытии, в том числе по нажатию на уведомление. Не устаревший — не перечитывается (тест на отсутствие запроса)
- [ ] T204 Строки «обновляется» и «не удалось обновить, повторить»; ошибка чтения не оставляет молча кэш с диска
- [ ] T205 Сторож мёртвого сокета: выбрать кадр проверки и порог, закрыть и соединиться заново

## Непрочитанные (3.2)

- [ ] T206 Запечатанная запись «виденное время» по чатам; обновляется, когда пользователь смотрит на чат
- [ ] T207 После чтения списка чатов: активность новее виденного → «непрочитано» и «устарел». Тесты: после push, после потерянного push, холодный запуск

## Уведомления (3.3) — `messenger-ui` и `wolp-android`

- [ ] T208 Мост: `Push.notifyMessage({conversationId, messageId, senderId})`; приложение убирает дубль по номеру сообщения общим списком с push
- [ ] T209 Интерфейс зовёт его, когда сообщение принято, а приложение не на экране или чат не открыт в фоне; подтверждение серверу — после
- [ ] T210 Уведомление без номера чата открывает список чатов

## Отметка «вышел» (3.4) — `wolp-android`
